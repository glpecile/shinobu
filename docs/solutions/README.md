# Solutions

One file per solved bug or non-obvious pattern, written the moment the fix ships —
not batched later. Keep entries short and greppable: what happened, what the fix was,
and why it wasn't obvious. Any planning pass must scan this folder before proposing a
refactor or new integration, so the same class of bug isn't re-solved from scratch.

Suggested filename: `<topic>.md`, e.g. `trakt-rate-limiting.md`,
`anilist-title-matching.md`.
