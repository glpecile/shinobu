## Why this matters

`package.json` pins `@swmansion/react-native-bottom-sheet` to the prerelease
`0.17.0-next.2`. The prerelease was needed for `ModalBottomSheet.onCloseRequest`
(Android Back closes the sheet). Stable `0.17.0` shipped that API on
2026-10-18, and `0.17.1` followed on 2026-10-22. Between `next.2` and stable,
upstream fixed several Android problems this app is exposed to: Fabric
mounting errors that blanked the app on repeated open/close, duplicate
`onIndexChange` on repeated scrim taps, scrim taps also pressing buttons
underneath, `'content'` detent sizing with `zIndex` children, and idle CPU
use while a sheet is mounted. Staying on the prerelease keeps those bugs and
hides future updates behind an exact pin.

Status of the other pin, for the record: `nitro-webview` must stay on its git
commit. Upstream PR #53 (the React Native 0.88 fix the app needs) merged
*after* the last published release (0.2.2 on 2026-10-18), and no later
version exists. Nothing to do there yet.

## Current state

- `package.json:13` — `"@swmansion/react-native-bottom-sheet": "0.17.0-next.2"` (exact pin).
- `bun.lock` — the matching lock entry.
- `src/components/sheet/index.tsx` — the **only** allowed import of the
  library (oxlint-enforced). It uses `BottomSheetProvider`, `ModalBottomSheet`,
  and the props `detents={[0, 'content']}`, `index`, `onCloseRequest`,
  `onIndexChange`, `onSettle`, `scrimColor`, `style`, `wrapNativeView` and
  `surface`. It does not set `scrollableNegotiation` or
  `disableScrollableNegotiation`.
- `src/components/sheet/index.web.tsx` — web Modal fallback; doesn't import the library.
- `docs/solutions/android-back-navigates-behind-sheet.md:6` says "Version
  0.17.0-next.2 adds `ModalBottomSheet.onCloseRequest`".

API compatibility, checked against the published 0.17.1 tarball: every prop
above still exists with the same name in `lib/typescript/src/BottomSheet.d.ts`
and `ModalBottomSheet.d.ts`. JS source differences from next.2 are a
`nativeID` on the internal content-height marker and a type formatting change.
The native iOS/Android sources changed: the content inset moved from top
padding to bottom padding, and the Android close-request routing was reworked.
That is why this needs a native rebuild and device QA.

Behaviour changes in the 0.17.0 release notes to watch in QA:

- The default `scrollableNegotiation` is `{ expand: 'handoff', collapse: 'initial' }`:
  dragging up on a scrollable can expand the sheet and keep scrolling without
  lifting the finger. Our sheets are content-height with an inner `ScrollView`
  (`SheetContent`), so check the log sheet with many tags.
- `detents`/`index` are now validated and throw on invalid values. We only
  pass `[0, 'content']` and `0 | 1`, which are valid.

Native build rule (AGENTS.md): `android/` and `ios/` are generated and never
edited. A native dependency change needs `bun ios.clean` / `bun android.clean`.
A `pod install` version mismatch means clean-prebuild, never `pod update`.

### Step 4: Native rebuild and device QA (owner, or an executor with simulators)

If you can't build native apps in your environment, stop after Step 3, set
the plan to `BLOCKED (needs device QA)` in `plans/README.md`, and hand the
checklist below to the owner.

Run `bun ios.clean` and `bun android.clean`, then check on each platform:

1. Long-press a card → card-actions sheet opens at content height, not full screen.
2. Open the log sheet on a movie with many Letterboxd tags. The sheet caps
   below the status bar, the content scrolls, and Confirm stays reachable.
3. Drag the sheet down → it closes. Tap the scrim → it closes once
   (on Android, no button underneath the scrim gets pressed).
4. Android only: open a sheet on a pushed details screen, press system Back →
   the sheet closes and the details screen stays.
5. Android only: focus the tags field in the log sheet → the sheet lifts with the keyboard.
6. Open and close a sheet 10 times quickly → no blank screen, no crash.

**Verify**: all six checks pass on both platforms.
